## server
- `server/app.py` - Flask API entrypoint for the desktop subtitle service, with backend health check plus auth APIs, admin APIs, Redis-backed IAP package APIs, backend-served admin web routes, hourly backend file logging setup, and proxy route composition.
- `server/logging_setup.py` - Configures hourly rotating backend log files under the root `logs/` directory, wiring Flask and Werkzeug logging into UTF-8 file output without duplicating handlers on repeated app initialization.
- `server/auth_routes.py` - Registers optional local auth endpoints with PBKDF2 password hashing, login by email or username, HS256 JWT access tokens, rotating refresh tokens, current-user lookup, logout revocation, admin access guards, and temporary-admin bootstrap integration while returning the latest per-user credit balance, premium state, and role state.
- `server/auth_identity.py` - Owns shared auth-side username normalization plus public-user shaping helpers, including the normalized premium flag, used by auth routes and admin routes so `auth_routes.py` stays below the 400-line guardrail.
- `server/auth_store.py` - Owns MySQL-backed auth persistence for registered users, usernames, roles, premium state, current credit balances, and refresh tokens, initializes or migrates the configured `audio_studio` auth schema, seeds the local demo user credit row, and now delegates credit-ledger mutations to `server/auth_credit_store.py` so the main auth store stays below the 400-line guardrail.
- `server/auth_credit_store.py` - Owns the MySQL credit-history ledger, typed credit balance mutations, admin credit grants or adjustments, and paginated per-user credit-history reads used by the admin detail page.
- `server/admin_store.py` - Owns admin-side auth-user queries for checking whether any persisted admin exists, summarizing users, paginating accounts, filtering the paginated user list by display name, username, or email search, loading a single user detail record, and applying admin role or premium or balance changes with credit-ledger integration.
- `server/admin_bootstrap.py` - Creates and logs the temporary in-memory bootstrap admin credentials when no persisted admin exists, logs the explicit skip reason when a real admin already exists, and clears that temporary state once a real admin account is created.
- `server/admin_routes.py` - Registers the admin-only backend API for completing temporary-admin bootstrap, reading paginated or searched user lists, loading per-user detail, requests, and credit history, adding credits from the admin detail page, updating user role or premium or balance, and listing recent backend requests.
- `server/iap_store.py` - Owns MySQL-backed IAP package persistence and schema creation, validates package ids, names, price or currency or credits fields, and supports listing, creating, updating, and deleting IAP catalog records.
- `server/iap_admin_store.py` - Owns MySQL-backed admin-only IAP configuration persistence for payment-hook API keys, pack function mappings, sale rules, and active API-key validation used by `/api/pay/info`.
- `server/iap_cache.py` - Owns the Redis cache helper for the public client IAP package list, targeting `localhost:6379` with the `audio_editor` key prefix and graceful fallback when cache access is unavailable.
- `server/iap_routes.py` - Registers the public client IAP package read API, the `/api/pay/info` payment-hook API-key validation endpoint, and admin-only IAP package, API key, pack function, and sale CRUD APIs, serializing package payloads and invalidating the Redis-backed public package cache after package mutations.
- `server/admin_web_routes.py` - Serves the standalone React admin frontend build from `admin-frontend/dist` for `/admin`, `/admin/login`, `/admin/setup`, `/admin/manage`, `/admin/iap`, and `/admin/users/:id`, exposes built `/admin/assets/*`, and redirects `/console` to the React management route.
- `server/proxy_routes.py` - Registers transcription, translation, and Vbee voiceover proxy endpoints, charges per-user credits when subtitle, translation, or voiceover jobs start, refunds failed start attempts with typed ledger metadata for admin history, records owned request ids, syncs `server_requests.status` from downstream status responses, preserves downstream status codes and error payloads for the desktop client, falls back to a MySQL-backed local translation job when the upstream worker-based service is unavailable, returns local translation downloads from database content, and proxies Vbee audio downloads back through Flask so the Electron renderer can auto-download the result without cross-origin issues.
- `server/proxy_route_helpers.py` - Owns the shared proxy-route helper functions split out of `server/proxy_routes.py`, including provider-response shaping, request-record persistence helpers, owned-request checks, translation fallback response helpers, and Vbee router URL resolution.
- `server/request_store.py` - Owns MySQL-backed persistence for server-managed request/job state, including user-owned transcription, translation, and voiceover request records plus local translation fallback job output, initializes the request tables, migrates legacy translation-job files into MySQL without creating new request files, lists recent request records for the admin console, and paginates per-user request history for the admin detail page.
- `server/translation_fallback.py` - Runs local subtitle translation jobs via `deep-translator`, stores user-owned job metadata and translated SRT output in MySQL through `server/request_store.py`, writes completed generic request records as `success`, and serves the fallback `start -> status -> download` flow used when the upstream translation service cannot accept work.
- `server/requirements.txt` - Lists Flask, HTTP client, translation, MySQL connector, and Redis client dependencies for the subtitle-service backend.
