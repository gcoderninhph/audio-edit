## Backlog
- [ ] Investigate or replace single-node Whisper provider concurrency - Current `pluja/whishper` runtime does not appear to provide true intra-node parallel transcription on the CPU profile. Direct internal probes to `http://whishper:8000/transcribe/` returned two simultaneous identical requests in about `3009ms` and `5826ms`, showing the second request effectively waits behind the first inside the provider. Container inspection showed `/bin/whishper` exposes no worker or prefork flags, Fiber reports `Processes = 1` with `Prefork = Disabled`, `transcription/main.py` starts `uvicorn.run(...)` with the default single worker, and `transcription/transcribe.py` loads a fresh `FasterWhisperBackend` model on every request before transcribing. Decide whether to cap each physical Whisper node to `maxConcurrentRequests = 1`, scale out with more node containers, or build a custom Whisper image that reuses loaded models and runs multiple ASR workers.
